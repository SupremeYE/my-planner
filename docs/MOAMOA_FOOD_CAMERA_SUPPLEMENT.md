# 음식 사진 촬영 보완 (2026-10-24)

## 보존과 구현

브랜치 `codex/moamoa-step3b4-food-records`, HEAD `becf876e865b7525d5d081583665d446ebef099c`에서 진행했다. 기존 미커밋 작업 706개 파일을 `/workspace/moamoa-backups/STEP3B4_WORKING`이 가리키는 복구 사본과 SHA-256 전부 대조했다. 삭제·초기화·커밋·Push·배포·운영 DB/Storage 접근은 하지 않았다.

`MoaFoodEditor.tsx`의 추가·수정 사진 영역에 두 동작을 제공한다.

- **사진 촬영**: 별도 file input, `accept="image/*" capture="environment"`. 사용자 클릭으로 후면 카메라 촬영을 요청한다. 기기/브라우저가 capture를 무시하거나 촬영 선택 메뉴를 표시할 수 있다. PC에서는 일반 파일 선택 창이 열릴 수 있으며 웹캠 촬영을 보장하지 않는다.
- **앨범에서 선택**: 기존 file input을 유지한다. capture 속성을 사용하지 않는다. OS에 따라 앨범 또는 파일 선택 UI가 표시되며 카메라 선택지가 함께 나올 수도 있다.

두 input은 같은 selectFile → 미리보기 → 명시적 저장 → 기존 확인 업로드 경로를 공유한다. 선택만으로 업로드/기록 저장하지 않는다. 선택 취소는 현재 파일·사진 URL·입력을 바꾸지 않는다. 파일 선택 후 input 값을 비워 같은 파일을 다시 선택할 수 있게 했다. 저장 중/실패 상태의 중복 동작 방지, 동일 사진 요청 UUID, upsert=false, 응답 유실 후 바이트 확인, 원본 보존 정책을 유지한다.

## 형식과 크기

허용 MIME: JPEG/PNG/WebP/GIF/AVIF/HEIC/HEIF. 파일당 최대 **10 MiB(10,485,760바이트)**이며 화면에는 10MB로 안내한다. 빈 파일·초과 크기·미지원 MIME은 업로드 전에 거부하고 기존 사진과 입력을 유지한다. MIME이 비어 있는 파일도 현재는 추측하지 않고 거부한다.

HEIC/HEIF는 변환하지 않고 원본 바이트와 MIME을 보존한다. 자동 검증은 전송/경로/제한 검증이며 **실제 HEIC 디코딩 성공이나 iPhone 호환성 검증이 아니다**. 브라우저가 HEIC 미리보기를 지원하지 않으면 사진 오류 안내를 표시한다. 실제 iPhone의 카메라 MIME, 방향/EXIF, HEIC 미리보기·재조회는 추가 확인해야 하며, 지원하지 않으면 JPEG 선택/촬영 설정 변경을 안내하는 것이 현재 대안이다. JPEG 파생 미리보기/변환을 도입하려면 원본 보존과 별도 검토가 필요하다.

## 자동 검증 범위

- Chromium 390px/1440px에서 두 버튼 → 실제 filechooser 이벤트 확인.
- 촬영 input의 accept/capture와 앨범 input의 capture 부재 확인.
- 가상의 촬영 결과 파일을 넣어 미리보기 → 음식명/날짜 → 업로드/저장 → Provider 재마운트 후 사진/기록 재조회.
- 촬영 선택 취소 시 기존 URL 유지, 앨범을 통한 사진 교체, 업로드 실패/응답 유실/DB 실패 후 재시도, 중복 방지와 원본 객체 유지.
- HEIC/HEIF 전송 원본 보존, 10MiB 경계·초과·빈 파일·미지원 MIME 검증.

**물리 카메라, iOS Safari, 홈 화면 PWA는 실행하지 않았다.** Chromium filechooser에 테스트 파일을 주입한 것을 실제 촬영 완료라고 표시하지 않는다. 스크린샷은 `docs/screenshots/moamoa-food/mobile-camera-options.png`, `desktop-camera-options.png`와 기존 업로드/실패/수정 캡처를 참고한다.

## 실제 iPhone 검증 — 모두 미실시

Safari와 홈 화면 PWA에서 각각 아래를 실행해야 한다.

1. 촬영 버튼 → 후면 카메라/촬영 선택 UI 및 권한 거부·취소 확인.
2. 촬영 완료 → 미리보기 방향/해상도/HEIC·JPEG MIME 확인.
3. 음식명/날짜 입력 → 저장 → 화면 재진입/새로고침 → 이미지 표시.
4. 기존 기록 사진 교체 후 저장 전 취소·파일 선택 취소 → 원본 유지.
5. 느린 연결·오프라인·업로드 실패 → 파일/초안 유지 → 명시적 재시도 → 중복 없음.
6. 앨범/파일 앱 선택, 같은 사진 재선택, 10MiB 이상 사진 안내.
7. 키보드·safe area·스크롤·저장 버튼의 접근성 확인.

## HTTPS 테스트 환경 구성안 — 배포하지 않음

- 운영과 분리된 Supabase 테스트 프로젝트와 테스트 사용자·테스트 사진 전용 버킷을 사용한다. 운영 DB/Storage/Secret을 복사하지 않는다.
- 별도 HTTPS 테스트 호스트에 개발용 음식 진입 경로를 명시적으로 허용하는 검증 빌드를 준비한다. 현재 Production 빌드는 개발 경로를 제거하므로 단순 Preview 배포만으로 이 경로가 열리지는 않는다.
- 테스트 도메인에만 Auth redirect 및 테스트 환경변수를 설정한다. AI는 mock 또는 비활성화하고, PWA는 별도 origin/manifest 범위로 운영 설치와 분리한다.
- 승인 후 격리 RLS/Storage 정책과 사진 업로드·재조회부터 검증한 다음 실제 iPhone Safari/PWA 체크리스트를 실행한다. 이 문서는 구성안이며 환경 생성/정책 변경/배포를 실행하지 않았다.
